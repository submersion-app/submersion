# 🎉 Submersion v1.7.2.4977 Release Notes

v1.7.2 adds the Site Seascape, which puts your dive sites on the real seafloor using published bathymetry, and opens a public beta channel so new work reaches you as soon as it is merged rather than at the next release. There is no database change in this release and nothing to migrate.

---

## ✨ New and improved

### Site seascape: view your dives and sites against the seafloor

The 3D view could previously only reconstruct a scene from compass heading and GPS position, which very few dive computers record, so most divers saw an invented shape. Seascape is anchored on the dive site instead and built from real published bathymetry, drawn from EMODnet, GMRT, and NOAA ETOPO, with the best available source for your location winning. Open it from the terrain button on any site that has coordinates. The scene shows the site pin and its maximum recorded depth, entry and exit markers, dead-reckoned dive paths, and nearby sites, with distance and depth axes always visible in your units. Hover any point on the seafloor to read its coordinates and depth.

Individual dives are draped over the same real terrain wherever a survey covers the site. A caption states which survey produced the seafloor and at what resolution, and says plainly when no survey was available and the seafloor is a synthesized shape rather than measured ground. Dive paths never deform the terrain, so what you see under the path is the real bottom. Attribution for all three sources is in Settings, under About.

### A beta channel you can opt into

Every change merged now produces a beta build on all five platforms, instead of work waiting weeks for the next release. On macOS, Windows, and Linux, Settings > About > Update channel switches between Stable and Beta in place, with no reinstall. On iOS and Android the same section links out to TestFlight and Play open testing, since the stores own enrollment there.

Beta builds may upgrade your dive log's database ahead of the stable release, so the app asks before switching and takes a backup automatically before any database upgrade. All devices that sync together should be on the same channel. Switching back to Stable never downgrades the app: you stay on the beta you have until a stable release is newer than it, then rejoin the stable line normally.

### Devices on different versions no longer collide

Because a beta device can now be ahead of a stable one, sync records the version that wrote each change. A device on the older version stops trying to read changes written in a newer format, keeps its place in the log, and shows a banner on the Cloud Sync page telling you how many devices are ahead of it. Nothing is dropped: update that device and the held changes arrive.

### Smaller additions

- **The Updates card is translated.** It was hardcoded English in every language.
- **The version in About is marked "(Beta)"** while you are on the beta channel, so you can always tell which line a device is on.

## 🐞 Bug fixes

- **Linux stops advertising an update you already have.** The updater compared its own three-part version against four-part release tags, so the banner never cleared.
- **The Windows in-app updater downloads again.** It was looking for an installer file name that is no longer published.
- **The version-mismatch screen shows the download address** instead of leaving you with nothing when the browser fails to open, and no longer promises a backup file that is not always written.
