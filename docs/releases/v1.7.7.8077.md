# 🎉 Submersion v1.7.7.8077 Release Notes

v1.7.7 brings 143 merged changes since v1.7.6, the largest release so far. The headliners are dive logs that shrink to roughly a tenth of their previous size, a proper recovery path when a database turns out to be newer than the app opening it, Suunto Cloud and Garmin Connect imports, USB downloads for the Scubapro G2 and Suunto EON Steel families, a rebuilt MacDive importer, real Linux packages, species photo tagging with an online lookup and 174 freshwater species, site suggestions from photo GPS, per-dive statistics charts, and a reworked dive planner. This release upgrades the database (schema 175 to 191) and compacts the file once, so please read the upgrade notes at the end.

---

## ✨ New and improved

### Dive logs a tenth the size

The second-by-second profile behind every dive chart used to be stored one database row per sample, and on a typical logbook those rows were about 90% of the file. They are now packed losslessly, one record per profile per source: a 1,040-dive test library went from 751 MB to 35 MB, and profile reads got several times faster. Charts, statistics, exports and sync are unchanged, and the data round-trips byte for byte. The raw bytes downloaded from your dive computer, kept so a dive can be re-parsed later, are now compressed too, typically 2.4 to 4.7 times smaller, and since backup retention keeps up to 13 copies of the database the savings multiply across your backups. Raw computer data now also travels in UDDF exports, in the standard's dive computer dump section, so Re-parse keeps working after a UDDF restore and every data source comes back with its original import date.

### When your data is newer than the app

If a beta build, or a backup restored from a newer build, had upgraded your database, the stable build refused to open it and its only button led to the stable download page: the exact build that had just refused the file. That screen is now titled "Your Data Is Newer Than This App", explains the likely causes, links both the stable and the clearly marked pre-release download pages, and, when the app finds the pre-upgrade backup it took automatically, offers a one-tap restore of it. Before swapping, it saves the newer database into your backups folder as a pinned backup so nothing logged in the newer build is lost. Pre-migration backup pruning was also corrected: it kept the three newest copies, which could all be too new for the build you had, and it now always retains the copy with the lowest schema version. Backups are additionally tagged with a non-identifying fingerprint of the device that wrote them, so future cleanups can never remove another device's only copy.

### Suunto Cloud and Garmin Connect imports

The Transfer page gains a Cloud section. Sign in to your Suunto app account or Garmin Connect account and dives come in through the same wizard a Bluetooth or USB download uses, so tanks, gas switches, duplicate detection and consolidation behave identically. Only a session token is kept in the platform keychain; the password is never stored, and Garmin's multi-factor challenge is supported. Both fetches are paged newest first (15 dives by default) with Load More and Fetch All, and the Garmin step lets you pick dives from a checkbox list. Garmin dives whose FIT file carries no GPS now take the activity position Garmin Connect reports. The import review list also gains a sort by date, depth or time.

### USB downloads for the Scubapro G2 and Suunto EON Steel families

Submersion now speaks USB HID on macOS, Windows and Linux. The Scubapro G2, G2 TEK, G2 Console, G2 HUD, G3 and Aladin Square, and the Suunto EON Steel, EON Core, D5 and EON Steel Black, are selectable under USB in the dive computer wizard, where before the only route (if any) was Bluetooth; the Aladin Square was previously unreachable altogether. Which hardware is supported comes straight from libdivecomputer's device tables. This path has not yet been verified against physical hardware, so reports from G2 and EON Steel owners are very welcome.

### A rebuilt MacDive importer

Importing a MacDive database used to decode profiles only for Shearwater computers, and later three Suunto models; everything else got a "use MacDive's XML export" warning. The importer now resolves the computer name MacDive stored against libdivecomputer's full device list, so every model Submersion supports is decoded, with a plausibility check (depth, duration, sample order, agreement with MacDive's own figures) before a profile is attached. For dives with no usable raw data, MacDive's own drawn profile turned out to be a simple fixed-key cipher, and it is now decoded as a fallback: on a 540-dive reference library every profile now imports, sample for sample. Photos referenced by a MacDive logbook are imported through the wizard's Photos step, linked in place from MacDive's image folder rather than copied. And a bug that imported EAN32 as 3200% oxygen, corrupting CNS and OTU, is fixed (dives imported before this fix need a re-import).

### Real Linux packages

The Linux download was a tarball of loose files that installed nothing, declared no dependencies, and gave no device permissions, so USB dive computers never appeared. Linux now ships .deb and .rpm packages built from the same binary: they add a desktop entry and icons, register with GNOME Software and KDE Discover, and install udev rules generated from libdivecomputer's device tables that grant USB access to the logged-in user with no group membership or re-login. One .rpm installs on Fedora, openSUSE and RHEL alike. The tarball remains for Arch, NixOS and others, now with install and uninstall scripts that report missing libraries with the exact apt, dnf, pacman or zypper command. Also on Linux: every export used to fail silently because there is no share sheet, and exports now open a save dialog; and the OAuth sign-in for Dropbox, Google Drive and Lightroom falls back through xdg-open and friends and always offers a Copy link button.

### Species, photos and a bigger catalog

Species is now a top-level destination in the desktop sidebar and the phone's More sheet, and "Marine Life" is called "Species" everywhere. You can tag the photos on your dives with the species in them, from the photo viewer or from a species' detail page, which gains a photo gallery; tagging a photo adds the sighting to that dive if it was missing, and tags sync between devices. Each tile on the Species page shows the species' newest photo, sighting rows show photo counts, and the media library gains a Species filter. When a species is not in the catalog, look it up on iNaturalist from the species editor, the dive picker or a site's nearby-species list: the lookup fills in common name, scientific name and category, with licensed photos and attribution, and sends nothing until you tap Look up. The bundled catalog gains 174 freshwater species (pike, perch, trout, carp, sturgeon, rift-lake cichlids, crayfish, turtles, otters, water plants and more) in all 11 languages, and it is now versioned, so future additions reach existing installs while any built-in species you edited is left exactly as you changed it.

### Site suggestions from photo GPS

The "GPS found in photos" banner used to appear only on the dive edit page, only from phone stills, and only offered to create a brand-new site. Photo location is now read on every platform, including desktop stills and videos from iPhones, most cameras and GoPros, using the photo taken closest to the dive's entry time. Before offering to create anything, the app matches the location against your own sites and the bundled catalog, so the suggestion can assign the nearest site, let you pick a nearby one, add coordinates to your current coordinate-less site, or create a new one with country, region and city prefilled. It appears on the dive detail page as well as the editor, importing photos across several dives prompts a review of all of them at once, and dismissals sync across devices.

### Statistics that show every dive

The depth, bottom time, weight, SAC and water temperature trend charts averaged each month over a fixed five-year window. They now plot every dive as its own point on a true date axis, with a rolling average on by default and an optional straight-line trend that reports a rate such as "+51.8 ft/yr" in your units; weekly and monthly averaging remain as options with a shaded min-to-max band. "All time" now reaches every dive, Last 5 years and Last 10 years join the date presets, and the statistics detail pages get their own filter button. The depth distribution chart extends to 130 m in 10 m steps with count and total time per bucket and per dive type, and dive site pages gain a computed Dive Statistics card (count, deepest, longest, average duration, first and last dive). The Water Type and Entry Method charts now count dives that inherit those values from their site.

### Combined and consolidated dives, taken apart and compared

A combined dive can now be separated back into its segments from the Data Sources section, each with its own profile, tank pressures, events and GPS fix, including dives combined before this update; the logbook details stay on the original dive, and the dialog says so first. Dives recorded on two computers get a full comparison: every per-computer analysis (deco, ceiling, NDL, TTS, gas, CNS, OTU, GTR and the rest) is computed independently and can be overlaid in the chart and its tooltip, tanks with the same mix are merged even when one side lacks pressure data, and legend toggles are coloured names you can click. The detail chart and sparklines now draw the active computer's series rather than an interleaved union, which fixed a sawtooth temperature line and stutter on consolidated dives.

### A reworked dive planner

Segments no longer carry a type you pick from a dropdown: descent, level, stop and ascent are read off the depths, so a leg can no longer be labelled Ascent while descending, and a new segment starts where the previous one ended. Tanks sit above the segments, saved cylinders can be added to a plan with one tap and any plan tank can be saved for reuse, and cylinder roles follow what the segments actually breathe. Three deco engine defects were fixed, including a schedule that could tell you to ascend through your own ceiling; ascent rates are now 9 m/min from the bottom, 6 between deep stops, 3 between shallow stops and 1 off the last stop; stops snap to whole minutes; and you can choose a last stop of 3, 4, 5 or 6 m. The ceiling shading on the plan chart now follows the selected contingency and is drawn only where a ceiling exists. Separately, a plan seeded from a previous logged dive came out permanently less conservative than a fresh plan regardless of surface interval, and now matches it stop for stop.

### Equipment records that satisfy an insurer

Every item gains SKU, Retailer and Web link fields beside the purchase date and price, shown on both the edit form and the detail card and carried through sync, backup and CSV export. A web link typed as a bare host is treated as https, and the detail row is tappable with a copy-link fallback. A new Documents card on the equipment detail page holds invoices, receipts and warranty paperwork, linked in place rather than copied, with PDFs opening in the in-app viewer; attachments are removed with the item when it is deleted.

### Nine new equipment types

Rash Guard, Snorkel, Tool, Instrument / Gauge and Compass each arrive with their own fields (sleeves and UPF rating, purge valve, gauge range and depth rating, balance zone and tilt tolerance) and their own icon, and the Other type moves off the wrench icon so it no longer looks like a tool. Undersuit and Base Layer become first-class types with a warmth rating and fill material, and gloves gain three-finger, dry glove liner and utility variants. Undersuit warmth and glove type feed the buoyancy engine, so swapping a light undersuit for a heavy one now shows up as its own lead term in a dive's Buoyancy section. UDDF and MacDive imports recognise the new types instead of filing them under Other or as a second drysuit, and an older version of the app shows them as Other rather than failing.

### Profile photos for divers and buddies

Divers and buddies can now carry a profile photo, with a circular crop tool at pick time. Photos are stored in the database itself, resized to 512 by 512, so they sync to your other devices and survive reinstalls; orientation is corrected and location metadata is stripped before saving. They show on buddy rows, the dive detail page and the Detailed PDF's diver page.

### Where your storage goes

A new Storage usage page under Settings reports what the database, media caches, staging files, map tiles, thumbnails, backups, temporary files and exports each occupy. Browse map tiles now live in their own cache capped at 5,000 tiles and swept after 30 days, while your downloaded offline regions are never capped or swept and each new region gets its own store so deleting it really frees the bytes. The media cache checks its budget on every launch, scratch files that nothing ever deleted (picked-file copies, abandoned uploads, transcode leftovers, stale thumbnails) are swept daily, and devices that never sync purge their deletion records after 30 days.

### One record per dive computer

The same physical computer could be saved more than once, most often one record per Apple device because each Mac, iPhone and iPad assigns its own Bluetooth identifier, with dives split between the records. Duplicates can now be merged from the dive computer list, from a computer's detail menu, or from a banner that appears whenever another record shares the serial; every dive, tank, profile and equipment link moves to the survivor and there is no undo. Related: a saved computer whose Bluetooth identifier changed used to scan for 35 seconds and fail, and the download now proceeds when exactly one discovered device matches the saved model, writing the new identifier back if the serial agrees.

### Seas named, place names repaired

The body-of-water field stayed empty for nearly every dive site because OpenStreetMap has no ocean or sea polygons. The app now ships the IHO Limits of Oceans and Seas table (101 named areas, in all supported languages) and consults it before going online, with the smallest area winning, so the Gulf of Aqaba beats the Red Sea and the Adriatic beats the Mediterranean; marine sites also need one online request instead of two. If your place-name language changed at some point and older sites hold English names while newer ones hold local ones, a new Refresh place names action in the site list re-looks-up every site with coordinates in the current language, and the same run is offered right after you change the language. This is the one action in the app that overwrites hand-typed location fields, and its dialog says so.

### Smaller additions

- **Choose which dive detail sections show, and how.** A display-options menu picks the sections and offers the existing Detailed layout or a new List layout that folds each section to a header row and lets you drag them into a new order.
- **The navigation customizer now saves the whole order**, not just the first three, and the desktop sidebar gets its own order behind a Phone / Desktop switch.
- **Find gear faster.** The equipment list gets a filter panel with a Category section alongside Status, advanced dive search gains an equipment picker so you can find every dive on which you used a particular regulator, and a pre-dive checklist item can be linked to one piece of gear so overdue service surfaces in the checklist itself.
- **Exclude a dive from statistics.** A dive can now be excluded from statistics, or from gas statistics only, in the editor or in bulk, with a badge explaining why it is not counted and a filter that finds your excluded dives. It stays fully visible and editable in the logbook.
- **GTR (gas time remaining)** joins the profile chart, either your computer's own or one calculated from your SAC and a reserve pressure set under Settings > Decompression.
- **Gas Calculators is a split view** like the rest of Planning instead of a sideways-scrolling tab strip: a list of the six calculators beside the selected one on wide windows, or a list that opens each on its own page on narrow ones. Nothing about the calculations changed, and typed values survive switching between them.
- **The trimix blender remembers your work.** Start and target pressure and mix, plus the fill gases, now persist across app restarts instead of resetting every launch. The fill-gas, blending-conditions and billing cards move behind a settings gear on the blender screen, with a second gear beside the cost card that jumps straight to the default settings and billing section, so the main screen shows only the blend. Cylinder sizes are now a single editable list of name and litres under that section, replacing the fixed presets in the cylinder dropdown.
- **The weight planner takes height into account** through an optional BMI term, matches the AL30 and AL40 stage entries in its catalogue correctly, and gains the AL100 as a built-in cylinder preset.
- **CCR ppN2, ppHe, gas density and MOD curves now follow the loop** instead of the first tank's fixed fractions, so MOD on a rebreather is the diluent's MOD.
- **The emergency card leads with your own insurer** once you record its 24-hour line on your insurance details, with the regional DAN or DES hotline as the fallback. The chamber directory gains 14 facilities across Belgium, the Netherlands and Luxembourg, now 223 in total.
- **The dashboard's red urgent banner is gone**; overdue gear shows as red chips at the front of the gauge strip, and safety chips show their alert state even if you hid them.
- **Last Dived sorts** for the sites list and the buddies list, never-dived entries always last.
- **Imported dives whose profile shows a deco obligation default to the Technical type** instead of Recreational, when the source carries no type.
- **The Detailed PDF logbook is finally detailed**: one dive per page with a vector profile, full notes, every cylinder, and field groups for conditions, team, equipment, technical data, marine life and signatures. Certification lists paginate instead of stopping after one page, every template prints in your units, and the Professional template is folded into Detailed.
- **The 3D seascape picks the best bathymetry source** by resolution and coverage and adds a high-resolution coastal tier for US waters, so Bonaire renders with a real coastline instead of a flat slab; and the depth axis in both 3D views now scales to the fetched terrain rather than the site's recorded maximum, which was squashing the terrain toward the surface.
- **The Cressi Leonardo's deco obligation and ascent-rate alarms** are now read correctly by libdivecomputer instead of flagging most of an ordinary ascent.
- **Your date format is respected everywhere**: Trips, Certifications, settings, media, safety, checklists, courses, buddies, backups, the GPS log and chart axes all follow the Manage > Units setting, and the calendar dialog stays in the app's language whatever format you choose.
- Google Drive now appears in the first-run wizard's Backup & Sync step.

## 🐞 Bug fixes

**Sync, backup and cloud storage**

- Google Drive sync could fail on every attempt with "Client is already closed" until the app was restarted, and Drive media transfers failed the same way after any token refresh. Both recover on their own now.
- Google Drive listings silently stopped at 100 files, so peer libraries could go unseen and media past the first 100 objects was invisible. Listings now page to the end.
- A fresh install on macOS could inherit the old install's sync identity, see the whole library as its own files, and offer Start Fresh over live data.
- Photos uploaded from the desktop showed as "Not backed up" on the phone and failed with "source unavailable"; a one-time repair runs at launch. Update both devices before their next sync.
- With iCloud as the media store on a Mac and an iPhone, the Mac's uploads could sit at "Waiting" forever after the second device connected. A library already split still needs a disconnect and reconnect, which the new "Transfers paused" notice explains.
- Adopting a large library from another device sat at "Pulling changes..." with a frozen bar and could hang the app. Progress now advances through every pass and the parser is many times faster.
- If one device's changes failed to read during a sync, the failure was silent and that device stopped merging. The Cloud Sync page now names the device and retries it next time.
- Sync files and peer-supplied GPS tracks were decompressed without limits, so one corrupt payload could exhaust memory on every device in the library. Both are now bounded and refused quickly.
- Reset Sync State could delete a sync export another process was writing at that moment.

**Dive computers**

- Every platform's translation of libdivecomputer's event codes was off by one past a certain entry, so ascent-rate alarms showed as Deco Violation on every computer (a Mares Sirius owner saw them all over a 16 m no-deco dive), and ceiling, deep stop and PO2 events were dropped. See the upgrade notes for re-parsing.
- A Ratio iX3M 2 on APOS5 firmware 5.2.11 imported every dive as 0 m and 0 minutes, and a 300 bar transmitter read half its pressure. Re-parse recovers the profiles.
- A Shearwater Petrel 2 failed every download on Android a few milliseconds after connecting, because Android chose the Classic transport on a dual-mode radio. The Windows half of that report is still open pending a log.
- A Shearwater Perdix 3 was rejected by the Android scanner because of a stray terminator byte in its advertised name.
- A Seac Tablet never appeared in a Bluetooth scan because libdivecomputer accepted only one exact name shape. It is discovered now, though its download still fails for a separate reason that is tracked.
- A Suunto Ocean was misidentified as an Oceans S1 and then failed to connect. It is now passed over honestly; Ocean owners should import from the Suunto app.
- Several Android and Windows Bluetooth failures either reported success on a dead link, hung for the full 15-second timeout, or blamed the wrong cause. They now fail fast with the real reason.
- Downloading from a saved computer listed the dives and then showed "Dives (0)" on the Review step, because a late device-info write rebuilt the page with an empty session.

**Imports and exports**

- Importing CSV, UDDF, SSRF or XML files could strand the wizard on a Map Fields step showing "0 of 0 columns", and Next could do nothing after a Peregrine download. A failed step now stays put and shows why, and duplicate detection is advisory rather than fatal.
- Subsurface UDDF dives entered without a time were dated the day of the import and numbered wrongly, and Subsurface trips were not imported at all.
- Writing dive metadata to a video could delete your original from your library, and on Apple platforms that deletion propagated through iCloud Photos. Video metadata writing is withdrawn on every platform; photo metadata writing is unchanged and edits in place.
- Photos imported as files sometimes showed a broken-image tile with a cloud badge even on the device that imported them. Thumbnails now resolve the same way the viewer does.

**Dive log and charts**

- Opening a dive in the editor and saving it unchanged silently reset eleven values, including the dive computer model, serial and firmware, deco algorithm and gradient factors, and the planned-dive flag. All survive a save now; values already wiped need a re-download or re-import.
- A star rating could never be removed. Tapping the current star, or a new clear icon, clears it, in the editor and in bulk edit.
- Capturing a buddy or instructor signature has never saved anything on any platform. Signatures now save, sync, render at the size you drew them, and stay out of the media library.
- Range-stats handles on the profile chart sat outside the plot, so the marker never lined up with the figures it reported; a related right-edge offset affected the gas strip, photo markers and hover mapping.
- The profile chart flashed once about 300 ms after a dive was first opened.
- Consolidating a dive while touching the chart could crash it with a range error.
- Consolidating tanks from two computers skipped the pressure check whenever any reading was missing, so a 207/63 bar tank could merge with a null/150 bar one silently.
- A dive combined from two file or cloud imports drew only one half on the detail chart.
- Date filters compared against the device's time zone offset rather than local midnight, so at UTC-5 "This year" dropped dives logged before 05:00 on 1 January. Filters are calendar days everywhere now.
- Opening Appearance > Dives > Dive List Fields pinned a CPU core and froze the app.
- In bulk edit, Tags > Add > Browse opened the picker behind its dialog where nothing could be tapped.
- Some dives showed the same dive type badge two or more times after syncing across devices. Duplicates are collapsed on upgrade and cannot return.
- Clicking zoom "+" on a chart made the reset button appear under the cursor, so a quick second click reset instead of zooming.
- The seasonal water temperature chart drew its labels off the grid lines and let unit-formatted labels wrap and collide.

**Planner**

- A new planner segment always started at 0 m and ended at 18 m regardless of the previous segment.
- On phones the planner pinned the chart and readouts at the top, leaving a third of the screen for the results. The page now scrolls as one.

**Equipment and safety**

- The Service Due equipment filter returned nothing, even for gear badged OVERDUE, because it read a retired service field.
- Filtering an item's maintenance history changed the rows but not the Total.
- Equipment value totals showed a bare "$" for both US and Canadian dollars; labels now carry the currency code.
- Trip checklists were only editable on liveaboard trips. The section now appears on every trip, with a Clear checklist action.

**Interface and platforms**

- The trip and certification lists, the update check's "Last checked" stamp and the purchase date field ignored the diver's date format.
- The More sheet on phones could grow under the Android status bar, hiding its title and close button.
- Offline map regions that were deleted freed no storage. New regions get their own store; regions downloaded before this update show an Unknown size and cannot be freed individually (see upgrade notes).
- The "Update Required" screen could not scroll, cutting content off on small windows and large text sizes.

## ⚠️ Upgrade notes

- **The database upgrades from schema 175 to 191.** The migration runs once on first launch and the app takes an automatic backup beforehand, so there is nothing you need to do first. The profile repacking then compacts the file once, which can take a little while on a large logbook; let it finish. The packed profile storage raises the sync compatibility floor, so update every device in your library reasonably soon; older devices are held from syncing until they update.
- **Re-parse your dives once after updating.** Three libdivecomputer corrections (the off-by-one event table behind false Deco Violation markers on every computer, the Ratio iX3M 2 APOS5 5.2.11 profiles, and the Cressi Leonardo deco obligation) apply only to new downloads. Open each dive computer's page and run "Re-parse all dives" to rebuild existing dives from their stored raw data.
- **Your dive count may change.** Planned dives that were never logged no longer count toward any statistic, so anyone who has used the planner will see counts and averages shift. Dives you exclude by hand are still counted for gear service intervals, course progress and the logbook number.
- **Planner schedules change slightly.** The corrected deco engine, new ascent rates and whole-minute stops mean existing plans will show slightly different stop times and runtimes.
- **MacDive gas mixes imported before this release** are inflated a hundredfold on any non-air tank and need a re-import or a manual correction.
- **Offline map regions downloaded before this release** cannot be separated from the shared tile cache after the fact. They keep working, show an Unknown size, and can only be freed by clearing the whole cache; regions downloaded from now on delete cleanly.
- **The weight planner's predictions move a little** for dives with a stage bottle (the AL30 and AL40 entries are now matched correctly), for divers whose profile records a height, and for anyone who re-types gloves or undergarments as the new equipment types.
- **Dive detail section order:** if you sync with a device still on an older version, that device falls back to its default section order. Nothing is lost.
- **"Marine Life" is now "Species"** throughout the app; the "Marine life" incident category in safety records keeps its name because it describes a cause of injury.
- **Linux requires glibc 2.38 or newer**, which has been true of every release since three bundled libraries need it; Debian 12, Ubuntu 22.04 and RHEL 9 cannot run Submersion. The new .deb and .rpm packages install to /usr/lib/submersion and show the package-manager upgrade command instead of a Download button when an update is available. If you were using the tarball, uninstall it before installing a package so the two do not shadow each other.
- **If you run beta builds alongside stable**, note that the pre-migration backup set now always keeps the copy with the lowest schema version, and the "Your Data Is Newer Than This App" screen can restore it for you. Restoring a pinned copy of the newer database later requires a build that supports its schema.
- **No minimum operating system change** on macOS, Windows, iOS or Android.
